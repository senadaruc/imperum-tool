# Clipboard History ("Copy Stack") — Design

**Date:** 2026-09-26
**Status:** Approved in conversation (pending spec review)
**Reference product:** CopyCat 1.0.2 (voprex.CopyCat), analysed on this
machine. Imperum Tool replaces it plus the Hammerspoon double-tap script.

## Problem

The user wants CopyCat's clipboard-history capability inside Imperum Tool:
copy several things, then choose what to paste. Two things CopyCat cannot
do drove this: its hotkey is a hardcoded ⌘⇧V (the user wants a double-tap
of plain ⌘V, currently bolted on with Hammerspoon), and its history is a
world-readable plain-JSON file.

## Goal

1. Record every copy (text, link, email, colour, image, video, file) with
   source app and time, honouring password-manager "concealed / transient"
   pasteboard types and a user-managed exclusion list.
2. **Double-tap ⌘V** opens a floating panel over the current app. A single
   ⌘V still pastes. Optional fixed ⌘⇧V hotkey. Also a Tap Gesture action.
3. Keyboard-first panel matching the CopyCat layout: search-as-you-type,
   category chips, day sections, ⌘1–9, ⌘P pin, Delete, Esc.
4. Return pastes the pick into the app the user was in: files as files,
   images as images, colours as colours, text as text.
5. History persists across restarts, encrypted at rest; pinned clips never
   expire. Optional session-only mode.
6. Menu-bar badge with the clip count and a small menu.
7. **Nothing leaves the Mac.** The only network call is favicon fetching,
   opt-in and off by default.

## Non-goals

- Automatic updates (Sparkle). App-wide concern; separate task.
- Sync, cloud, or sharing of any kind.
- Rich-text / HTML preservation. Text clips are stored as plain strings.
- App Store distribution (Imperum Tool is Developer ID only already).

## Architecture

Pure logic in `ImperumCore` (testable, no AppKit); AppKit shells in
`ImperumTool`. Follows the existing TapDetector / TapGestureController
split.

```
ImperumCore                          ImperumTool
─────────────────────────────        ─────────────────────────────────────
Clip, ClipKind                       ClipboardWatcher   (NSPasteboard poll)
ClipClassifier                       CmdVTap            (CGEvent tap)
CaptureVeto                          ClipPaster         (pasteboard + ⌘V)
ClipStore   (dedupe, limits, pins)   CopyStackPanel     (NSPanel + SwiftUI)
ClipGrouper (Pinned/Today/…)         PanelModel
ClipFilter  (query + category)       ClipboardStatusItem(badge + menu)
DoubleTapDetector (state machine)    ClipboardSettingsTab
ClipArchive (AES-GCM index + blobs)  ClipboardController (wires it all)
```

`ClipboardController` is owned by `AppController`, created at launch like
`tapGestures`, and is a no-op when the master switch is off.

## Data model

```swift
public enum ClipKind: String, Codable { case text, link, email, color, image, video, file }

public struct Clip: Codable, Identifiable, Equatable {
    public let id: UUID
    public let kind: ClipKind
    public let capturedAt: Date
    public let sourceAppName: String
    public let sourceBundleID: String?
    public var isPinned: Bool
    public let title: String        // first line / filename / hex / "Image 256×256"
    public let payload: Payload
}

public enum Payload: Codable, Equatable {
    case text(String)               // text, link, email, color (hex form)
    case fileURLs([URL])            // file, video
    case blob(id: UUID, utType: String, pixelSize: CGSize?)   // image (PNG on disk)
}
```

Text payloads are stored inline. Images go to a blobs folder as PNG keyed
by `id`; the index holds only metadata, so search never touches the disk.
File and video clips store the URLs; a bookmark is not needed because the
app is not sandboxed.

### Classification (`ClipClassifier`)

Read the richest representation first: file URLs → image → colour →
string. Then:

| Result | Rule |
|---|---|
| video | file URL whose `UTType` conforms to `.movie` |
| file | any other file URL |
| image | `NSImage`-readable data (PNG/TIFF/JPEG) |
| color | `NSColor` pasteboard type, or string matching `#RGB[A]`, `#RRGGBB[AA]`, `rgb()/rgba()/hsl()` |
| link | string that parses as an http(s) URL with a host and no whitespace |
| email | string matching a single RFC-5322-ish address |
| text | everything else; empty / whitespace-only strings are dropped |

### Veto rules (`CaptureVeto`) — evaluated before reading content

Skip the change when any is true:

1. Pasteboard carries `org.nspasteboard.ConcealedType`,
   `org.nspasteboard.TransientType`, or `org.nspasteboard.AutoGeneratedType`.
2. Frontmost app's bundle ID is in the exclusion list.
3. Capture is paused.
4. The change count equals the one `ClipPaster` just produced (our own paste).

### Store (`ClipStore`)

- In-memory array, newest first. Pinned clips are surfaced first by the
  grouper, not by reordering the array.
- **Dedupe:** a new clip whose `kind` and payload equal an existing clip
  replaces it at the top, keeping the existing `id` and pin state.
- **Limits:** after every insert, drop unpinned clips beyond
  `maxStackSize` (default 500) and unpinned clips older than
  `retentionDays` (default 30). Pinned clips are never dropped.
- **Mutations:** insert, togglePin, delete, clearAll. Each schedules a
  debounced (500 ms) save unless session-only mode is on.

### Grouping and filtering

`ClipFilter` applies the category chip (All or one `ClipKind`; Links and
Emails are separate chips) then a case-insensitive substring match of the
query against `title` and, for text-family clips, the payload.
`ClipGrouper` yields sections in order: Pinned, Today, Yesterday, then one
section per calendar day (localised long date). Dates use the user's
calendar and time zone.

### Archive (`ClipArchive`)

Location: `~/Library/Application Support/Imperum Tool/Clipboard/`
- `index.bin` — JSON of `[Clip]`, encrypted with AES-GCM.
- `blobs/<uuid>.png` — image payloads, each encrypted the same way.

Key: 256-bit symmetric key generated on first use, stored in the login
Keychain as a generic password (service `io.imperum.tool.clipboard`,
account `archive-key`). Loss of the key means the archive is unreadable;
the app then starts with an empty stack and rotates the key. Files are
written atomically (temp file + rename), permission 0600.

Session-only mode (`clearOnQuit`): nothing is written; on enable, the
existing archive is deleted; on quit, memory is cleared.

## Double-tap ⌘V (`DoubleTapDetector` + `CmdVTap`)

`DoubleTapDetector` is a pure state machine:

```swift
public enum KeyInput { case cmdV(at: TimeInterval, isRepeat: Bool), other(at: TimeInterval), timerFired }
public enum Decision { case hold, swallow, pasteNow, openPanel, passThrough }
```

Rules (window `W`, default 0.30 s, range 0.20–0.40 s):
- `cmdV` while idle → `.hold` (caller swallows the event and arms a timer for `W`).
- `cmdV` with `isRepeat` while holding → `.swallow`.
- `cmdV` while holding → `.openPanel` (caller cancels the timer). Back to idle.
- `other` while holding → `.pasteNow` then the event is passed through
  (preserves "⌘V then Enter" order). Back to idle.
- `timerFired` while holding → `.pasteNow`. Back to idle.
- anything while idle that is not `cmdV` → `.passThrough`.

`CmdVTap` installs one active `CGEvent` tap (`.cgSessionEventTap`,
`.headInsertEventTap`, key-down only). It requires Accessibility, obtained
through the existing `ActionRunner.ensureAccessibility()`. Every event we
post ourselves carries `kCGEventSourceUserData = 0xC0C0`; the tap passes
those through untouched. If macOS disables the tap (timeout), the tap
re-enables itself on the `tapDisabledByTimeout` event.

When the trigger setting is "⌘⇧V only", the tap is not installed at all
and a Carbon `RegisterEventHotKey` (key 9, modifiers cmd+shift) is used,
mirroring CopyCat. "Both" installs both.

## Paste flow (`ClipPaster`)

1. Write the clip to `NSPasteboard.general` in native form:
   - file / video → `writeObjects([NSURL…])`
   - image → PNG data + TIFF
   - color → `NSColor` object plus its hex string
   - text / link / email → string
2. Remember the resulting `changeCount` so the watcher does not re-record it
   (it does move the clip to the top).
3. Order the panel out. The panel is non-activating, so the previous app
   still owns focus; no re-activation and no race.
4. Post ⌘V via `ActionRunner.pressKey(9, .maskCommand)` with the user-data
   marker set.

## Panel (`CopyStackPanel`, `PanelModel`)

- `NSPanel`, style `[.nonactivatingPanel, .titled(hidden), .fullSizeContentView]`,
  level `.floating`, `canBecomeKey = true`, `hidesOnDeactivate = false`,
  collection behaviour `[.canJoinAllSpaces, .fullScreenAuxiliary]`.
- 640 × 520 pt, centred on the screen containing the mouse (from the menu:
  the main screen). `NSVisualEffectView` material `.hudWindow`, 14 pt radius.
- SwiftUI content, top to bottom: search field (auto-focused) with match
  count; chips All · Text · Links · Emails · Colors · Images · Videos · Files;
  sectioned list (kind glyph / 32 pt thumbnail / colour swatch, title,
  "source · HH:mm", ⌘1–⌘9 on the first nine visible rows); footer hints
  ↑↓ Navigate · ←→ Category · ↩ Paste · ⌘P Pin · ⌫ Delete · esc Close.
- Keys: ↑↓ move (wrapping off), ←→ change chip, ↩ paste, ⌘1–9 paste that
  row, ⌘P toggle pin, ⌫ delete selected (Delete key when the search field
  is empty; otherwise it edits the query), esc close. Any other key goes to
  the search field. Click on a row pastes.
- Closes on: paste, esc, click outside, app switch, screen lock, or the
  panel losing key status.
- Link favicons: only when `showFavicons` is on. Fetched once per host via
  `URLSession` to `/favicon.ico`, cached in memory and on disk (unencrypted,
  it is public data) under `Clipboard/favicons/`. Link glyph otherwise.

## Menu-bar item (`ClipboardStatusItem`)

Second `NSStatusItem` next to the existing WindowServer gauge (untouched).
Button shows a rounded badge with the clip count (template-rendered so it
follows menu-bar contrast; drawn dimmed while paused). Menu:

```
14 clips                 (disabled)
────────────
Show Copy Stack          ⇧⌘V shown only when that trigger is enabled
Clear Stack…
Pause Capture / Resume Capture
────────────
Settings…                ⌘,
Quit Imperum Tool        ⌘Q
```

Clear Stack shows an `NSAlert` ("This removes every clip from memory and
deletes the local archive.") then calls `clearAll` and deletes blobs. Pause
state persists in config.

## Settings — new "Clipboard" tab

Built like `TapGesturesSettingsTab`; values live in `AppConfig`
(UserDefaults) and apply live via `config.onChange`.

**Capture & trigger**
- Enable clipboard history (master switch).
- Trigger: Double-tap ⌘V / ⌘⇧V / Both. Double-tap delay slider 200–400 ms
  (visible when double-tap is on).
- Maximum stack size (stepper, 20–2000, default 500).
- Forget unpinned clips after N days (stepper, 1–365, default 30).
- Clear stack when Imperum Tool quits (toggle, default off) with the note:
  "Off by default: your clips are kept in a local encrypted file so your
  history is there next time. Turn on for session-only memory. Either way,
  nothing leaves this Mac."
- Show clip count in the menu bar (default on).

**Privacy**
- Text: "Clipboard content never leaves this Mac. Copies made in excluded
  applications are not captured."
- Show website icons for links (default off) + note that the domain of a
  copied link is contacted.
- Excluded Applications: table of app icon + name; **Add Application…**
  (`NSOpenPanel`, `.application` only, starts in /Applications, stores the
  bundle ID); **Remove**. Pre-seeded: `com.1password.1password`,
  `com.agilebits.onepassword7`, `com.bitwarden.desktop`,
  `com.apple.keychainaccess` (all removable).
- **Clear All Clipboard Data** (same as Clear Stack).

Launch at login and Version already exist (General tab, About panel) and
are not duplicated.

**Tap Gestures:** new `TapAction.Kind.showCopyStack` ("Show Copy Stack"),
category Screenshots & clipboard; `ActionRunner` forwards it to the
controller.

## Config keys (AppConfig)

`clipboardMaxStack` (500), `clipboardRetentionDays` (30),

Added 2026-09-27 (see `2026-09-27-clipboard-limits-and-shortcuts-design.md`):
`clipboardCategoryLimits` ([String: Int], keyed by category, absent = off)

## Error handling

- Accessibility not granted: tap is not installed; badge menu shows
  "Grant Accessibility to enable ⌘V…" which opens the existing prompt; the
  ⌘⇧V hotkey still works, and the panel still opens from the menu.
- Archive unreadable (corrupt or key missing): log, start empty, rotate key.
- Blob missing for an image clip: row shows the image glyph; paste is a
  no-op with a HUD message; the clip is deleted.
- Pasteboard read throws or is empty: ignore the change.
- Event tap disabled by the system: re-enable; if that fails, show a HUD
  once and fall back to hotkey mode for the session.

## Performance

- Poll every 250 ms, main queue, comparing `changeCount` only (nanoseconds).
- Filtering is in memory over ≤ 2000 clips; the panel renders from the
  already-filtered array, so opening is one frame.
- Image thumbnails are downscaled to 64 px on capture and stored beside the
  blob as `blobs/<uuid>.thumb.png` (encrypted like the blob) and held in
  memory as `NSImage`, so the list never decodes full images.

## Addendum (2026-09-26): terminal picker

Adds `copystack`, a standalone TTY picker, and routes the double-tap ⌘V /
⌘⇧V trigger to it instead of the SwiftUI panel when the frontmost app is a
supported terminal.

### Architecture

- `CopyStackKit` (a library target, shared by `copystack` and `ImperumTool`)
  holds everything with no AppKit/terminal I/O: `CLIArgs` (argv parsing),
  `KeyParser` (raw bytes → `Key`), `PickerModel` (pure state/reduce),
  `FrameRenderer` (state → ANSI text), `Sanitize`/`DisplayWidth`,
  `Protocol`/`ProtocolCodec` (the wire format), `SocketPath`, `HostCommand`
  (per-terminal AppleScript/CLI strings, pure), and `FocusWait`.
- `Sources/copystack` is the executable: `TTYSession` (raw mode, alternate
  screen, `select(2)`-based polling, signal-safe restore) plus `main.swift`,
  which parses argv, connects over the socket, and either prints `list`
  output or runs the interactive `KeyParser` → `PickerModel` → `FrameRenderer`
  loop.
- In `ImperumTool`, `CopyStackServer` owns the Unix socket
  (`RequestHandler` from `CopyStackKit` over a `ClipBackend` adapting
  `ClipStore`), `TerminalHosts`/`HostCommand` open and position a host
  window, and `PickSession` drives one end-to-end session: open the host
  window, arm a 3s connect timeout for the picker's `hello`, track the
  pending paste from the socket, and run `FocusWait` (a pure state machine)
  once the picker's connection closes, to decide when it's safe to post
  ⌘V back into the origin terminal (wait for it to be frontmost and
  focused with the picker window gone, nudge once if slow, give up with a
  HUD hint after a timeout).
- Socket protocol ops (newline-delimited JSON, `Sources/CopyStackKit/Protocol.swift`):
  `hello` (optionally carrying a session token), `list`, `get`, `paste`,
  `copy`, `pin`, `delete`. Clips cross the wire as `ClipSummary`, whose
  text preview is cut to 2048 UTF-8 bytes (`ClipSummary.defaultPreviewLimit`)
  at a grapheme boundary — search inside the picker (`ClipFilter`, reused
  unchanged from the panel) therefore only sees that much of a long clip's
  body, unlike the panel, which filters the full in-process `Clip`.

### Hosts

| App | Open | Sizing | Close |
|---|---|---|---|
| Ghostty | AppleScript (`new surface configuration`); falls back to an `openApp` launch of a new instance | AppleScript path has no size property (fixed 900×560 on screen); the `openApp` fallback sizes itself via `--window-width/--window-height` | Ghostty's own `close window` AppleScript verb (its windows reject the standard "close" event) |
| cmux | cmux's own CLI (`new-window` + `send`) if the CLI is reachable, else AppleScript `perform action "text: …"` | No sizing mechanism at all (CLI or AppleScript) — fixed 900×560 | The CLI's `close-window` (cmux windows reject the standard "close" event too) |
| iTerm2 | AppleScript `create window with default profile command` | Sets `columns`/`rows` natively | AppleScript close by window id |
| kitty | `openApp` launch of a new instance with `-o initial_window_width/height` | Sizes itself at launch | No scriptable close by id; the new instance is simply terminated |
| Terminal | AppleScript `do script` | Sets `number of columns/rows` natively | AppleScript close by window id |
| Warp | Not supported — always falls back to the panel | — | — |

Whichever launch strategy wins, `TerminalHosts.position` polls (up to 1.5s)
for the AX window carrying the picker's OSC-2-set title
(`Copy Stack · <first 6 hex of the session token>`), raises it, and centres
it under the mouse at a fixed 900×560 unless the launch already sized it.

### Security

- The socket (`~/Library/Application Support/Imperum Tool/copystack.sock`,
  falling back to a `tmp/io.imperum.tool.copystack.sock` path if the home
  directory one would exceed `sun_path`'s 103-byte limit) is created with
  its parent directory at mode `0700`; the socket file itself is `0600`,
  so only the same local user account can connect. `IMPERUM_COPYSTACK_SOCK`
  overrides the path (tests use this).
- The server only runs while both "Enable clipboard history" and "Allow
  command-line access" are on, and stops (removing the socket) when either
  is turned off or the app quits.
- Every clip-derived string that reaches a terminal frame or an AppleScript
  string literal — title, file names, `sourceAppName`, the typed query —
  goes through `Sanitize` before rendering, so a maliciously named clip or
  file can't inject terminal escape sequences into `copystack`'s frame or
  spoof AppleScript.
- No clip content ever appears in a process's argv: `--session` is a random
  128-bit hex token (`PickSession.randomToken`, `SecRandomCopyBytes`),
  checked in `CLIArgs.parse` to be 8-64 hex characters before it can reach
  an OSC 2 title-setting escape sequence, and is otherwise meaningless
  outside identifying the session over the socket.
- `RequestHandler`'s pin/delete/paste/copy errors are surfaced in the
  picker's footer rather than silently dropped, and any socket error is
  treated as a lost connection: the tty is restored and the process exits
  with the standard "not running" message.

### Settings

Settings › Clipboard › Terminal adds: the terminal-picker toggle, the
command-line-access toggle, a cmux socket-password field (only needed if
cmux's own Settings has one set; stored in Imperum Tool's own preferences,
not the Keychain), a per-terminal status row (Ready / automation denied /
not running / launch failed / picker did not start), and the
"Install command-line tool…" button (falls back to a copyable `ln -s`
command when the app isn't bundled with `copystack` yet, e.g. a dev build).

### Packaging

`copystack` ships inside the app bundle at `Contents/MacOS/copystack`,
built and signed by `build.sh` with its own identifier
(`io.imperum.tool.copystack`) before the main executable and bundle are
re-signed. The app carries the `com.apple.security.automation.apple-events`
entitlement and an `NSAppleEventsUsageDescription` in `Info.plist`, both
needed to script the terminal hosts above.

### Testing

Unit-tested in `CopyStackKitTests` (238 tests): `CLIArgsTests` (every
grammar form and error case), `KeyParserTests` (byte-by-byte and
across-feed-boundary decoding, UTF-8/CSI/paste edge cases), `PickerModelTests`
/`FrameRendererTests` (reduce/render, scroll math, sanitisation),
`ProtocolTests` (wire round-trips, `ClipSummary` truncation),
`SocketPathTests`, `HostCommandTests` (the exact AppleScript/CLI strings
per host), `FocusWaitTests` (every wait/nudge/post/timeout transition),
`TerminalAppTests` (bundle-id detection incl. the cmux debug build's
suffixed id), `RequestHandlerTests`, and `UnixSocketTests` for the
transport itself.

Not unit-tested, manual only: actually opening/sizing/closing a window in
each live terminal app (needs that app installed, running, and Automation
access granted); the tmux popup binding end-to-end (needs an attached tmux
client); `PickSession`'s real-world `Timer`-driven focus wait against an
actual window manager; the Settings tab's live per-terminal status text;
and running the real `copystack` binary against the real running app's
socket (Task 8's report covers exercising `copystack` itself against a
stand-in socket server instead, since starting/stopping the real app
during development was out of scope).
